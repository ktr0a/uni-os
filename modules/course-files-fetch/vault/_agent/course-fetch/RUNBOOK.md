# Course pick-up: runbook

> [!info] Experimental, Windows only
> A small PowerShell task on the laptop files course files that an agent downloaded in the student's logged-in browser. It trusts no request: any session can write to the vault. Full spec and threat model: the framework's `modules/course-files-fetch/README.md`. The role that uses it: [../roles/course-files-fetch.md](../roles/course-files-fetch.md).

## The flow
1. The fetch session downloads one file in the student's browser (the browser is logged in; the password step stays with the student) and checks that the download finished.
2. It writes a request into `pending/` (with `request_pickup.py`, or by hand, see below).
3. The laptop task (every minute, hidden; default name "Uni OS course pick-up") checks the request and the downloaded file, copies the file into the course folder, verifies the copy's SHA-256, sends the Downloads original to the Recycle Bin, and writes `done/<id>.result.json`. The request moves to `done/<id>.request.json`.
4. The requester reads the result and, for `filed`, re-checks the hash on its own copy of the vault (the storage sync takes 1 to 5 minutes).

The policy the laptop applies (allowed hosts, target folders, limits, date guards) is in [pickup-policy.md](pickup-policy.md), generated by the installer. The laptop reads its own copy outside the vault, so editing that page changes nothing.

## Requesting
**With the helper** (Python 3.11+, any machine that sees the vault):
```
python "<framework>/modules/course-files-fetch/scripts/request_pickup.py" --vault "<vault>" "<file name as the browser saved it>" "<course folder>/<official subfolder>"
```
Options: `--approved-large` (the student approved a file over the size limit), `--no-wait`, `--machine <computer name>` (only that machine's pick-up handles it), `--status <id>` (result of an earlier request), `--pending` (list waiting requests).
Exit codes: 0 filed or already there (hash checked here), 1 refused, not found, changed on the server or failed, 2 usage error, 4 no answer yet (the request stays in `pending/`).

**By hand** (any agent with file tools):
1. Write `pending/<YYYYMMDD-HHMMSS>-<name with anything but A-Z a-z 0-9 . _ - replaced by _, at most 60 chars>.json` containing
   `{"file": "<exact file name>", "target": "<course folder>/<official subfolder>", "requested_at": "<ISO time with offset>", "approved_large": false}`
   (write it under another name first, e.g. `.<id>.json.part`, then rename: the task only reads `*.json`).
2. Wait for `done/<id>.result.json` (check every 10 s, give up after 15 min: laptop off).
3. For `filed`: compare the result's `sha256` with the SHA-256 of `<vault>/<target>/<file>` once your copy of the vault has synced.

## Result
`done/<id>.result.json`: `{"id", "file", "target", "status", "reason", "size", "host", "sha256", "vault_sha256" (only for changed-on-server), "at"}`. `host` is the download's origin host from its Zone.Identifier stream; URLs are never recorded.

| status | Meaning | What to do |
|---|---|---|
| `filed` | copied, hash verified, original in the Recycle Bin | log it in [course-fetch-log.md](course-fetch-log.md) |
| `already-there` | the same file (same hash) is already in the vault; the download went to the Recycle Bin | log "already there" |
| `changed-on-server` | the vault has a different file with this name; nothing overwritten, the download stays in Downloads | log it, tell the student; replace only with the student's yes via the coordinator (old copy to `z_archive/<course folder>-outdated-YYYY-MM-DD/`, then request again) |
| `rejected` | the request broke a rule (reason says which: name, type, folder, date guard, host, size) | fix the request; a host or folder that should be allowed needs a config change and the student re-running the installer |
| `not-found` | no matching download newer than the age limit within the wait (30 min) | the download never landed: check the browser's download list, download again in a new tab, request again |
| `failed` | an error, e.g. the copy failed its hash check (the partial copy was removed) | report it; the laptop's `pickup.log` has details |

## What the laptop checks, in order
1. The request is valid JSON (a broken one may still be syncing: it waits up to the wait time, then `rejected`). A request naming another machine is left alone.
2. The file name is plain (no folders, no `\ / : * ? " < > |`, no leading dot, no trailing dot or space, at most 200 characters) and its type is allowed (documents and source files, never programs).
3. The target is exactly one of the allowed official folders (case-sensitive) and exists; no date guard blocks the name.
4. Downloads holds the exact name, or the browser's numbered copy `name (1).ext` (the newest wins), at most 12 hours old; otherwise it waits up to 30 minutes, then `not-found`.
5. The download's `Zone.Identifier` stream names an allowed host (`HostUrl`; the referrer only if the config allows it). No stream, no host: `rejected`.
6. Size within the limit, or `approved_large`.
7. Destination exists: same hash = `already-there`, different = `changed-on-server`. Otherwise copy with "create new" (can never overwrite), verify the hash, then Recycle Bin the original = `filed`.

## Troubleshooting
- **No answer (exit 4):** the laptop is off or asleep, the task is disabled, or the sync is slow. The request stays in `pending/` and is handled when the laptop wakes. On the laptop: Task Scheduler shows the task's last run; `pickup.log` in the install folder (default `%USERPROFILE%\Documents\uni-os\course-pickup\`) has one line per outcome: `<ISO time> <status> | <file> | <target> | <reason>`.
- **Many `not-found` in a row:** unfinished `.crdownload` files or a blocked "download multiple files" prompt. Stop, report, wait for the student.
- **`rejected` for the host:** the file came from a host not in the policy (e.g. a file server the LMS links to). Ask the student; if it is an official source, add it to the course's `fetch_sources` (or `course_fetch.extra_hosts`) and the student re-runs the installer on the laptop.
- **`rejected`, "target folder does not exist":** the folder is in the policy but not in the vault yet. The student re-runs the installer (it creates missing target folders below an existing course folder); never create a course folder from a VM or cloud session.
- **Stop or start the task** (on the laptop, Windows PowerShell): `Disable-ScheduledTask -TaskName "Uni OS course pick-up"` / `Enable-ScheduledTask -TaskName "Uni OS course pick-up"`.
